# BLTS Knowledge Base

这是一个以 **Markdown + GitHub** 为底层、以统一网页为阅读入口的个人知识库。

知识内容仍由真实目录和 Markdown 文件承载；网页只扫描目录、生成索引并负责展示。新增或调整文档后，不需要手工同步网页菜单。

## 知识目录

```text
knowledge-base-blts/
├── 本部/
├── 外交部/
├── 技术部/
│   └── 软考/
├── 前沿部/
├── 商务部/
├── 艺术部/
├── site/                    # 统一网页界面
├── scripts/                 # 索引生成与内容校验
└── .github/workflows/       # 自动校验与构建
```

## 一级目录职责

- `本部/`：健康管理、健身目标、生活习惯与日常系统
- `外交部/`：个人成长、做人原则、心理模式、人际关系与人格体系
- `技术部/`：技术积累、软考、工程实践与技术壁垒
- `前沿部/`：AI 前沿、自媒体、内容选题、AI 变现、创意和待验证方向
- `商务部/`：理财、股票、投资、商业研究与 CFA
- `艺术部/`：审美、人像摄影、拍摄技巧与作品复盘

## 网页结构

网页按以下路径浏览：

```text
知识库总入口 → 部门 → 主题或知识库 → 文档
```

阅读页提供左侧目录树、全文搜索、正文渲染、右侧本文目录、SVG、Mermaid、知识图谱和深浅主题。目录与搜索索引均在构建时从 Markdown 自动生成。

## 本地检查

需要 Node.js 22 或兼容版本：

```bash
npm run check
```

命令会先检查一级目录、Markdown 标题、相对链接和不应进入成品内容的对话式语句，再把站点生成到 `dist/`。

`dist/` 是构建产物，不作为知识源维护，也不提交到仓库。

## 云端构建与发布边界

GitHub Actions 会在拉取请求和 `main` 分支更新时执行校验与构建，并保存一份仅仓库协作者可下载的短期预览产物。

仓库包含私人知识。个人账户下，从私有仓库发布的 GitHub Pages 网站仍可能对公网开放，因此在没有独立访问控制前，不启用自动 Pages 发布。

## 内容原则

- 新知识直接写入对应部门的 `.md` 文件。
- 目录尽量保持在「部门 → 主题 → 文档」三层左右。
- 同一主题只保留一个主文件，跨主题关联使用相对链接。
- 图片、视频等大文件不直接提交到 GitHub；必要的小型 SVG 图可以随文档保存。
- 不保存密码、Token、私钥、Cookie、身份证件号码等高敏感凭据。
