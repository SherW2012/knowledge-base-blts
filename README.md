# BLTS Knowledge Base

这是一个以 **GitHub + Markdown + Web Application** 为底层的个人知识与工作系统。

Markdown 负责长期知识沉淀，但 BLTS 不等于文件夹和 Markdown 阅读器。每个部门都可以同时拥有两类能力：

1. **应用与工作台（Applications）**：可交互的软件模块、看板、自动化流程和数据工具。
2. **知识与资料（Knowledge）**：由真实目录和 Markdown 文件承载的长期知识、参考资料与复盘。

网页是统一入口，负责部门导航、应用路由、知识目录、全文搜索和各种交互模块。

## 系统结构

```text
BLTS/
├── 本部/
├── 外交部/
├── 技术部/
│   └── 软考/
├── 前沿部/
├── 商务部/
├── 艺术部/
├── radar/                  # AI 情报雷达配置与采集逻辑
├── radar-data/             # 自动生成的机器数据
├── site/                   # Web Application
├── scripts/                # 构建、校验和自动化脚本
└── .github/workflows/      # 自动运行、校验与发布
```

## 部门模型

部门不是文件夹的同义词，而是一个独立工作域。

例如前沿部可以同时包含：

- AI 情报雷达：独立交互应用
- 未来的选题工作台、趋势看板等应用
- AI 与变现：知识主题
- 创意与新点子：知识主题
- AI 信息源与关注列表：长期资料

应用通过 `site/site-config.json` 注册，拥有独立路由与交互界面；应用的运行数据不进入 Markdown 知识目录。只有经过人工判断、值得长期保留的信息才沉淀为知识文档。

## 一级目录职责

- `本部/`：健康管理、健身目标、生活习惯与日常系统
- `外交部/`：个人成长、做人原则、心理模式、人际关系与人格体系
- `技术部/`：技术积累、软考、工程实践与技术壁垒
- `前沿部/`：AI 前沿、自媒体、内容选题、AI 变现、创意和待验证方向
- `商务部/`：理财、股票、投资、商业研究与 CFA
- `艺术部/`：审美、人像摄影、拍摄技巧与作品复盘

## 知识浏览结构

知识内容仍按以下路径浏览：

```text
系统总入口 → 部门 → 知识主题 → 文档
```

应用则使用：

```text
系统总入口 → 部门 → 应用与工作台 → 独立应用
```

阅读页提供左侧目录树、全文搜索、正文渲染、右侧本文目录、SVG、Mermaid、知识图谱和深浅主题。目录与搜索索引均在构建时从 Markdown 自动生成。

## 本地检查

需要 Node.js 22 或兼容版本：

```bash
npm run check
```

命令会先检查一级目录、Markdown 标题、相对链接和不应进入成品内容的对话式语句，再把站点生成到 `dist/`。

`dist/` 是构建产物，不作为知识源维护，也不提交到仓库。

## 云端构建与发布边界

GitHub Actions 会在拉取请求和 `main` 分支更新时执行校验与构建，并保存预览产物。自动化模块可以拥有独立 workflow，例如 AI 情报雷达的定时扫描。

## 内容原则

- 新知识直接写入对应部门的 `.md` 文件。
- 新工具、看板、数据处理流程优先考虑注册为部门 Application，而不是伪装成 Markdown 文档。
- 目录尽量保持在「部门 → 主题 → 文档」三层左右。
- 同一主题只保留一个主文件，跨主题关联使用相对链接。
- 自动抓取结果属于机器数据层，不自动进入永久知识库。
- 图片、视频等大文件不直接提交到 GitHub；必要的小型 SVG 图可以随文档保存。
- 不保存密码、Token、私钥、Cookie、身份证件号码等高敏感凭据。
