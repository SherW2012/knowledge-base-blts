# AI 代理量化交易方案可行性评估

> 评估对象：DeepSeek V4 Pro + Pi Agent + OKX Agent Skills / CLI + OKX 模拟盘  
> 原始方案：[AI 交易员第一步，用 DeepSeek 跑通量化交易](https://x.com/bozhou_ai/status/2092162592966053926?s=20)  
> 评估日期：2026-08-25  
> 归口：商务部

## 一、执行结论

**建议：条件性立项，但只立“内部教学与工程验证 PoC”，不立“自动赚钱产品”或“实盘交易系统”项目。**

这套方案的工具链是真实存在的：DeepSeek 已正式提供 V4 Pro API；Pi 支持 API Key 和自定义模型提供商；OKX 已发布官方 Agent Trade Kit、CLI、Skills 和模拟交易 API。因此，从行情读取、生成 Python、执行回测、dry-run 到模拟盘订单预览，工程上可以跑通。

但“流程跑通”不等于“策略有效”，更不等于“可以商业化或投入真实资金”。原方案只有约 300 根 1 小时 K 线，覆盖约 12.5 天，无法跨越不同市场状态；MA5/MA20、RSI14、ATR14 是常见指标组合，没有证据证明其在手续费、点差、滑点和参数漂移后仍有稳定超额收益。

商务判断如下：

| 方向 | 结论 | 说明 |
| --- | --- | --- |
| 内部教学实验 | **GO** | 工具齐全、成本可控、可通过模拟盘隔离资金风险 |
| 工程原型与风控验证 | **条件性 GO** | 必须补齐权限隔离、幂等、异常恢复、长周期验证和审计日志 |
| 课程、模板、实验室产品 | **条件性 GO** | 可卖“可复查的实验流程”，不能卖收益承诺 |
| 交易信号订阅 | **暂缓** | 策略无独特优势，回测证据不足，存在合规和声誉风险 |
| 自动实盘交易 | **NO-GO** | 当前阶段没有满足资金安全、策略稳健性与持续运维要求 |

综合可行性评分：**64/100**。其中技术实现 82，教学产品 78，工程可靠性 55，策略有效性 30，实盘安全性 25，商业合规 45。

## 二、方案中已经做对的部分

### 1. 工具与架构路径成立

- DeepSeek 官方已发布 V4 Pro，并支持 API 和 Responses API，模型名可通过官方模型列表动态确认。[DeepSeek V4 Pro 发布说明](https://api-docs.deepseek.com/news/news260813/)
- Pi 是可调用终端和本地工具的编码代理，官方文档支持 API Key、认证文件及自定义模型提供商。[Pi Providers 文档](https://pi.dev/docs/latest/providers)
- OKX 官方 Agent Trade Kit 提供 MCP、CLI 与 Skills，可访问行情、账户、现货及衍生品交易能力；工具在本机运行。[OKX Agent Trade Kit](https://www.okx.com/docs-v5/agent_en/)
- OKX 官方支持模拟盘 API，模拟请求需要明确使用模拟交易环境。[OKX API 文档](https://www.okx.com/docs-v5/en/)

### 2. 操作顺序基本正确

原方案采用“行情 → 本地数据 → 回测 → dry-run → 订单预览 → 人工确认 → 模拟盘执行”的顺序，比直接让模型下单安全得多。它还强调了以下正确原则：

- 只使用已收盘 K 线；
- 用 `shift(1)` 避免当前 K 线信号在当前 K 线成交；
- 显式计入手续费、点差和滑点；
- 先生成订单预览，再人工确认；
- 只用 BTC-USDT 现货模拟盘，不用杠杆；
- 保存数据、参数、日志和报告，支持复查。

这些设计适合作为量化交易工程入门实验。

## 三、不能据此证明“可赚钱”的原因

### 1. 样本只有约 12.5 天

300 根 1H K 线只能覆盖 12.5 天，还要扣除指标预热期。这个样本无法代表牛市、熊市、震荡、高波动、低流动性和突发事件等不同市场状态，也难以产生足够交易次数。

第一阶段至少应采集 2—4 年数据，并划分为：

- 训练期：用于形成规则；
- 验证期：用于调整有限参数；
- 样本外测试期：只做最终检验；
- 滚动前推期：检查参数随时间失效的问题。

### 2. 策略没有可识别的独特优势

均线交叉加 RSI 过滤属于公开且常见的趋势策略。它可以作为检查数据、回测和订单流程的“测试载荷”，但不能自动形成交易优势。策略是否成立，必须和以下基线比较：

- 买入并持有；
- 只使用 MA5/MA20；
- 随机入场但保持相同持仓周期；
- 不同参数区间下的稳健性；
- 不同交易品种和不同市场阶段的表现。

如果收益只存在于一组精确参数，稍微改变 MA、RSI 或费用就消失，应视为过拟合。

### 3. 成交模型仍然过于理想

原方案要求计入成本，但没有规定如何估算历史点差和滑点。用当前 ticker 或 orderbook 不能还原历史成交条件。若仅在收盘价上加一个固定滑点，结果仍可能偏乐观。

至少需要明确：

- 下一根 K 线开盘成交还是限价成交；
- 买卖方向的点差如何处理；
- 手续费按 maker 还是 taker；
- 订单未成交、部分成交和最小下单量如何处理；
- ATR 保护价位是否真正转化为可执行的退出规则；
- 绩效年化、无风险利率、夏普值和最大回撤的统一计算口径。

### 4. 回测和模拟盘都不能替代真实市场检验

模拟盘能够验证 API、状态机和下单参数，但其撮合、深度、延迟和成交概率不等同于真实市场。即使模拟盘盈利，也只能说明流程运行，不能证明实盘收益。

## 四、主要工程与安全缺口

### 1. “凭证留在本机”不等于模型无法接触凭证

Pi 可以调用 bash、读取文件和执行 CLI。若它和 OKX 配置运行在同一操作系统用户下，仅靠提示词禁止读取密钥，不构成真正的安全边界。恶意依赖、提示注入、模型误操作或脚本漏洞仍可能访问本地配置。

建议改为：

- 用独立系统用户或容器运行实验；
- 行情阶段只提供无需账户权限的公共行情接口；
- 回测阶段完全断开 OKX 凭证；
- 模拟交易阶段使用独立 demo 凭证，只开读取与交易权限；
- 永远关闭提币、转账和实盘 profile；
- 对可执行命令设置白名单，不以自然语言提示词代替权限控制；
- 日志统一脱敏，禁止保存环境变量和完整配置文件。

### 2. 依赖安装存在供应链风险

`curl | sh`、全局 npm 安装以及可执行 Skills 都能在本机运行代码。Pi 官方也提示第三方包可以执行代码并影响代理行为。因此 PoC 应锁定版本、核验来源和许可证，并在隔离环境中安装。

原文中的 OKX CLI 包名目前与 OKX 官方 Skills 一致，为 `@okx_ai/okx-trade-cli`；仍应在运行前以官方仓库的版本要求为准。[OKX 官方 Skills](https://github.com/okx/agent-trade-kit/blob/github-main/skills/okx-cex-trade/SKILL.md)

### 3. 缺少订单幂等和状态机

“不要重复输出同一信号”还不足以防止重复下单。需要持久化以下状态：

- `signal_id`：品种、周期、K 线结束时间和策略版本的组合；
- `client_order_id`：每个信号唯一；
- 状态：检测、预览、已确认、已提交、已接受、部分成交、已成交、已撤销、失败；
- 重启恢复：进程重启后先查询订单状态，再决定是否继续；
- 超时与重试：查询可以重试，写操作不得盲目重试。

### 4. 停止机制不完整

保护价位只被写进订单预览，并不意味着系统已经部署服务器端止损。若本地脚本退出、网络中断或机器休眠，本地停止逻辑可能失效。真实资金阶段必须使用交易所可验证的保护订单，并在提交后反查其有效状态。

## 五、商业机会判断

### 最可行：教学与实验室产品

可以将其包装为“AI 量化交易工程实验室”，出售的是：

- 标准化的环境检查；
- 可复查的数据与回测模板；
- 模拟盘订单状态机；
- 风控清单和审计报告；
- 面向开发者或企业培训的课程。

用户买到的是学习路径和工程工具，而不是收益承诺。该方向开发成本低、验证周期短，也更容易控制法律与声誉风险。

### 次可行：代理交易的风控与审计组件

比“再做一个交易策略”更有差异化的方向，是提供代理权限隔离、命令白名单、审批、订单幂等、日志脱敏、异常恢复和审计报表。这些能力可以适配多个模型和交易所，形成基础设施产品。

### 暂不建议：信号订阅或代客自动交易

该方向需要持续证明策略优势，还会涉及不同地区对数字资产服务、投资建议、营销、KYC、数据保存和客户资金的监管要求。服务是否可以提供取决于经营主体、客户所在地和具体产品形态，进入前必须由专业法律与合规人员按司法辖区审查。OKX 的可用产品和 API 要求也会因地区变化，不能把教程中的注册链接作为正式商务入口。

## 六、建议的 PoC 方案

### 阶段 0：工具与安全验收，2 个工作日

- 锁定 Pi、DeepSeek 和 OKX CLI 版本；
- 在容器或专用系统用户中安装；
- 代码审查 Skills 和安装脚本；
- 只读取公共行情，不配置交易凭证；
- 验证日志不包含密钥、环境变量和账户隐私。

通过条件：依赖可复现安装，权限边界可通过技术手段证明，而不是只依赖提示词。

### 阶段 1：研究级回测，5—10 个工作日

- 获取至少 2—4 年 1H 数据；
- 建立训练、验证、样本外和滚动前推测试；
- 加入真实费率、点差压力测试和滑点区间；
- 对比买入持有和简单基线；
- 做参数扰动、缺失数据和极端行情测试。

通过条件：样本外扣费后为正；参数小幅变化不导致结果崩溃；交易次数足以分析；最大回撤处于预先批准范围。夏普值、收益率或单次胜率不得单独作为通过依据。

### 阶段 2：模拟盘稳定性观察，至少 4—8 周

- 每根新 K 线只产生一个确定性 `signal_id`；
- 全部订单使用唯一 `client_order_id`；
- 测试网络中断、进程重启、API 限流和部分成交；
- 验证人工审批不可绕过；
- 每日核对本地状态与 OKX 订单状态。

通过条件：零重复订单、零越权写入、日志完整率 100%、异常恢复可复现、模拟成交与理论成交偏差可解释。

### 阶段 3：商务复审

只在前述阶段全部通过后选择下一步：

1. 发布内部培训材料；
2. 制作可销售的实验室模板；
3. 将风控与审计能力独立成产品；
4. 是否研究小额实盘，另行立项，不自动继承本 PoC 的批准。

## 七、立即修订清单

原教程在内部采用前应做以下修改：

1. 将“AI 交易员”改为“AI 辅助量化实验”，避免暗示模型具备稳定交易能力。
2. 将 300 根 K 线降级为接口冒烟测试，不用于策略结论。
3. 删除非官方注册链接，统一使用 OKX 官方入口。
4. 把版本号、命令和 profile 选项设为运行时检查项，不写死。
5. 将行情、回测、模拟交易拆成三个隔离环境和三套权限。
6. 增加依赖锁定、命令白名单、幂等键、状态机和故障恢复测试。
7. 明确 ATR 保护价位的执行方式，而不是只计算一个数字。
8. 在所有展示结果中同时给出样本区间、交易次数、总成本、基线和样本外表现。

## 八、最终立项意见

商务部建议以两周为首个检查点，预算只覆盖隔离环境、数据整理、回测框架和模拟盘状态机。首阶段不设置收益 KPI，不连接实盘，不开发“自动赚钱”营销话术。

如果目标是教学或验证 AI Agent 调用交易工具，成功概率约为 **80%—90%**；如果目标是用当前 MA/RSI/ATR 策略直接获得可持续实盘收益，现有证据下成功概率应视为 **低于 20%**。这两个概率衡量的是不同目标，不能相互替代。

因此，本方案的正确商业定位是：**先卖可复查的实验能力和风控基础设施，再决定是否继续研究交易策略；不要先卖收益故事。**
