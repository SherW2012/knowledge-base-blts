# 构件、中间件与 ADL

## 1. 这几个概念为什么放在一起

构件技术、中间件和 ADL 都服务于“怎样描述和组织软件体系结构”，但三者角色不同：

```text
构件：系统由哪些可复用单元组成
连接件：这些单元怎样交互
中间件：运行时提供通用通信和基础服务
ADL：用什么语言正式描述这些结构关系
```

## 2. 软件构件

软件构件可以理解为具有明确接口、可以独立部署或复用的软件单元。

一个构件通常关注：

- 提供哪些接口；
- 需要哪些外部接口；
- 内部实现被封装；
- 可以被替换、组合或复用。

构件与普通类的区别在于层次更高。类主要是程序设计层的类型单元，构件往往封装多个类、资源和实现细节，对外暴露更粗粒度的能力。

## 3. 构件模型

构件模型会规定构件怎样定义、交互、部署和运行。

典型关注点包括：

- 接口描述；
- 生命周期；
- 事件与消息；
- 事务；
- 安全；
- 部署；
- 运行容器。

历史上常见的构件模型包括 COM/DCOM、CORBA Component Model、EJB 等。考试重点一般不是记产品版本，而是理解它们都试图通过标准化接口和运行环境支持构件复用与组合。

## 4. 连接件

体系结构中的连接件描述构件之间怎样交互。

它可能表现为：

- 方法调用；
- RPC；
- 消息队列；
- 事件；
- 数据流；
- 共享数据访问；
- 网络协议。

因此体系结构不能只列出“有哪些模块”，还必须说明这些模块通过什么机制协作。

## 5. 中间件

中间件位于应用程序和操作系统/网络基础设施之间，为分布式应用提供通用服务。

```text
业务应用
   ↓
中间件
   ↓
操作系统 / 网络 / 数据库等基础设施
```

常见中间件能力：

- 远程通信；
- 消息传递；
- 事务；
- 服务发现；
- 身份认证；
- 数据访问；
- 对象管理；
- 负载均衡等。

中间件的核心价值是把很多重复的分布式基础能力从业务代码中抽离出来。

## 6. 常见中间件类型

### 6.1 RPC / 远程对象中间件

让应用像调用本地过程或对象一样调用远程能力。

### 6.2 消息中间件

通过消息队列或发布订阅机制让系统异步通信。

优点常包括：

- 发送方和接收方解耦；
- 削峰；
- 异步处理；
- 提高故障隔离能力。

### 6.3 事务中间件

为跨多个资源或服务的事务协调提供支持。

### 6.4 数据访问中间件

屏蔽不同数据源的访问差异，提供相对统一的接口。

## 7. 中间件与操作系统的区别

操作系统管理 CPU、内存、设备、进程等基础资源；中间件建立在操作系统和网络之上，为应用提供更高层的通用分布式服务。

```text
硬件
 ↓
操作系统
 ↓
中间件
 ↓
业务应用
```

所以“中间件”不是内核的一部分，也不是具体业务功能。

## 8. ADL 是什么

ADL（Architecture Description Language，体系结构描述语言）用于描述软件体系结构中的核心元素及关系。

典型 ADL 会描述：

- 构件 Component；
- 连接件 Connector；
- 接口；
- 配置 Configuration；
- 约束；
- 行为或属性。

与普通编程语言相比，ADL 关注的是系统级结构，而不是函数和算法实现。

## 9. ADL 与 UML

UML 是通用建模语言，可以表达类、交互、构件、部署等多种视角；ADL 更专注于体系结构本身，通常对构件、连接件、配置和体系结构约束有更明确的语义。

可以这样理解：

```text
UML：通用建模
ADL：专门描述体系结构
```

两者可以结合，而不是互相排斥。

## 10. 架构描述中的构件、连接件与配置

一个简单体系结构：

```text
[Web构件] --HTTP--> [订单服务构件] --SQL--> [数据库构件]
```

其中：

- 方框是构件；
- HTTP、SQL 访问关系可以看作连接机制；
- 整体“谁连谁”的拓扑就是配置。

ADL 的价值在于把这种结构从随意画图提升为具有明确语义、可以分析和检查的模型。

## 11. 接口

构件通常区分：

- **提供接口**：构件对外提供什么服务；
- **需求接口**：构件运行需要外部提供什么服务。

合理的构件组合要求一方的需求接口能够由另一方的提供接口满足。

## 12. 构件复用

构件复用通常要求：

- 接口稳定；
- 内部实现封装；
- 对环境依赖明确；
- 粒度合适；
- 有清晰版本和部署机制。

复用并不等于“复制代码”。真正的构件复用强调以独立单元形式被组合和替换。

## 13. 构件与服务

构件和服务都强调接口，但视角不同：

- 构件偏向软件实现和部署单元；
- 服务偏向通过网络接口暴露业务能力。

在 SOA 中，一个服务内部可能由一个或多个构件实现。相关内容见[Web Service与SOA](../17-面向服务架构SOA/03-Web Service与SOA.md)。

## 14. 做题快速识别

```text
可复用、可替换的软件单元 → 构件
构件之间通信机制 → 连接件
应用与操作系统之间的通用分布式服务 → 中间件
描述构件、连接件、配置的专用语言 → ADL
```

## 核心关系

```text
体系结构
= 构件 + 连接件 + 配置 + 约束

中间件提供运行时通用能力
ADL提供体系结构的正式描述能力
```
