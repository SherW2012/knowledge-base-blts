# UML 核心图与关系

## 1. UML 在软考里怎么考

UML（Unified Modeling Language，统一建模语言）用一组标准图描述系统的结构和行为。

软考不要求把 UML 全部规范背完，常考的是：

- 图是描述“静态结构”还是“动态行为”；
- 类之间的关系；
- 用例图参与者与用例关系；
- 顺序图、状态图、活动图分别适合描述什么；
- 构件图和部署图的区别。

## 2. 结构图与行为图

可以先按用途分两大类：

```text
UML
├── 结构类图：系统有什么
│   ├── 类图
│   ├── 构件图
│   └── 部署图
└── 行为类图：系统怎么动
    ├── 用例图
    ├── 顺序图
    ├── 状态图
    └── 活动图
```

## 3. 类图

类图描述类、接口以及它们之间的静态关系。

### 3.1 泛化/继承

```text
子类 ——▷ 父类
```

表示“is-a”。

例如：

```text
猫 是 动物
```

子类继承父类的属性和行为，并可以扩展或重写。

### 3.2 实现

类实现接口时通常使用虚线加空心三角箭头。

```text
具体类 - - -▷ 接口
```

它表达“这个类实现了接口规定的操作”。

### 3.3 关联

关联表示对象之间存在比较稳定的结构关系。

例如：

```text
教师 —— 课程
```

关联可以带多重度：

```text
1
0..1
*
1..*
```

### 3.4 聚合

聚合是较弱的整体—部分关系，部分可以脱离整体独立存在。

```text
班级 ◇—— 学生
```

空心菱形位于整体一端。

### 3.5 组合

组合是更强的整体—部分关系，部分的生命周期通常依赖整体。

```text
订单 ◆—— 订单项
```

实心菱形位于整体一端。

### 3.6 依赖

依赖表示一个元素临时使用另一个元素。

例如：方法参数、局部变量或临时调用。

依赖通常比关联关系更弱。

## 4. 五种关系快速排序

从“关系强弱和结构稳定性”的理解上，可以记：

```text
依赖 < 关联 < 聚合 < 组合
```

泛化/实现属于另一类“类型层次关系”，不与上面简单放在同一条强弱链中。

最容易混淆的是聚合与组合：

```text
聚合：部分可以独立存在
组合：部分强依赖整体生命周期
```

## 5. 用例图

用例图从系统外部使用者角度描述“谁使用系统完成什么目标”。

核心元素：

- **参与者 Actor**：与系统交互的外部角色；
- **用例 Use Case**：系统提供的一项用户目标；
- **系统边界**：哪些用例属于当前系统。

参与者不一定是人，也可以是外部系统、设备或其他角色。

## 6. include 与 extend

### include

一个用例**必然复用**另一个公共用例时使用 include。

```text
提交订单 → include → 身份验证
```

可以理解为：执行主用例时，被包含用例是固定需要的一部分。

### extend

某个附加行为只在特定条件下发生时使用 extend。

```text
支付订单 ← extend ← 使用优惠券
```

主用例本身可以独立完成，扩展用例是条件性的附加行为。

快速记：

```text
include：必做、公共复用
extend：可选、条件扩展
```

## 7. 顺序图

顺序图强调多个对象之间的消息交互顺序，时间通常从上向下推进。

典型问题：

```text
用户 → 控制器 → 服务 → 数据库
```

如果题目关心“先调用谁、再调用谁、消息怎么返回”，优先想到顺序图。

## 8. 状态图

状态图描述**一个对象**在事件驱动下如何从一种状态转到另一种状态。

例如订单：

```text
待支付 → 已支付 → 已发货 → 已完成
   ↓
 已取消
```

核心元素：

- 状态；
- 事件；
- 转移；
- 守卫条件；
- 动作。

如果题目强调“对象生命周期”“状态迁移”，优先想到状态图。

## 9. 活动图

活动图描述工作流或业务流程中的活动顺序、判断、并行和汇合。

例如：

```text
提交申请
   ↓
资格检查
 ┌─┴─┐
通过  不通过
 ↓      ↓
审批   结束
```

活动图更像流程图，但 UML 活动图还能够表达并发分支、同步汇合等行为。

如果题目强调“业务流程怎么走”，优先想到活动图。

## 10. 顺序图、状态图、活动图区别

| 图 | 主要观察对象 | 重点 |
|---|---|---|
| 顺序图 | 多个对象 | 消息先后顺序 |
| 状态图 | 单个对象 | 生命周期与状态迁移 |
| 活动图 | 一段流程 | 活动、判断、并发与工作流 |

## 11. 构件图

构件图描述软件构件、模块及其依赖关系。

例如：

```text
Web前端 → 订单服务 → 支付适配构件
```

它关注软件交付单元和逻辑构件组织，不强调这些构件最终部署在哪台物理机器上。

## 12. 部署图

部署图描述软件制品部署到哪些硬件节点或运行环境。

例如：

```text
浏览器
   ↓
Web服务器
   ↓
应用服务器
   ↓
数据库服务器
```

它关心“软件运行在哪里”。

因此：

```text
构件图：软件怎么组成
部署图：软件部署到哪里
```

## 13. UML 与 4+1 视图

UML 是一种建模语言；4+1 是一种架构视图组织方法。两者不是同一个层级。

一个 4+1 视图可以选择不同 UML 图表达。例如：

- 逻辑视图可用类图；
- 进程视图可用顺序图、活动图等；
- 开发视图可用构件图；
- 物理视图可用部署图；
- 场景视图可用用例图或交互图。

相关内容见[软件架构的4+1视图](../09-系统架构设计基础/02-软件架构的4加1视图.md)。

## 14. 做题快速识别

```text
类、接口、继承、聚合 → 类图
用户角色、系统功能目标 → 用例图
多个对象消息时间顺序 → 顺序图
一个对象状态变化 → 状态图
业务流程、判断、并行 → 活动图
软件模块/构件依赖 → 构件图
服务器/节点/部署位置 → 部署图
```

## 核心关系

```text
类图：静态类型结构
用例图：外部角色与功能目标
顺序图：对象之间消息时序
状态图：单个对象生命周期
活动图：业务和工作流程
构件图：软件构件组织
部署图：软件与物理节点映射
```
