# 软件可靠性基础与计算

## 1. 可靠性相关概念

可靠性关注系统在规定条件和规定时间内无故障运行的能力。

软考常把几个相近概念放在一起考：

- 故障 fault；
- 错误 error；
- 失效 failure；
- 可靠性 reliability；
- 可用性 availability；
- 可维护性 maintainability。

可以按因果链理解：

```text
内部缺陷/故障
      ↓
产生错误状态
      ↓
错误传播到系统边界
      ↓
用户可观察到服务失效
```

不同教材对 fault/error/failure 的中文翻译可能存在差异，做题时以题目采用的术语为准，但要理解它们通常表示“原因 → 内部异常状态 → 外部服务失败”的层次。

## 2. MTTF、MTTR、MTBF

### MTTF

MTTF（Mean Time To Failure）表示平均无故障运行时间，常用于不可修复系统或描述一次失效前平均运行多久。

### MTTR

MTTR（Mean Time To Repair）表示发生故障以后平均需要多长时间完成修复并恢复服务。

### MTBF

MTBF（Mean Time Between Failures）表示两次故障之间的平均时间。

在经典可修复系统模型中常近似理解为：

```text
MTBF = MTTF + MTTR
```

考试题如果给出具体定义，按题干定义计算。

## 3. 可用性计算

经典稳态可用性公式：

```text
A = MTTF / (MTTF + MTTR)
```

也常写成：

```text
A = MTTF / MTBF
```

前提是题目中的 MTBF 按 `MTTF + MTTR` 定义。

例如：

```text
MTTF = 999小时
MTTR = 1小时
```

则：

```text
A = 999 / (999 + 1)
  = 99.9%
```

这说明提高可用性有两条基本路线：

- 延长无故障运行时间；
- 缩短故障恢复时间。

## 4. 可靠性与可用性的区别

可靠性强调“在一段时间内不出故障”；可用性强调“需要服务时系统能不能用”。

一个系统可能偶尔故障，但如果恢复特别快，可用性仍然很高；反过来，一个系统故障次数不多，但每次修复时间很长，可用性可能并不好。

```text
可靠性更关注：少坏
可维护性更关注：坏了以后容易修
可用性综合体现：少坏 + 快修
```

## 5. 串联系统可靠度

如果系统由多个必须同时正常工作的独立构件串联组成：

```text
A → B → C
```

任何一个构件失效，系统都失效。

若各构件可靠度分别为 `R1、R2、...、Rn`，且相互独立：

```text
R串 = R1 × R2 × ... × Rn
```

例如两个模块可靠度都是 0.9：

```text
R串 = 0.9 × 0.9 = 0.81
```

串联构件越多，整体可靠度通常越低。

## 6. 并联系统可靠度

如果多个独立构件形成冗余，只要至少一个正常系统就能工作：

```text
A ─┐
   ├→ 输出
B ─┘
```

系统失效的条件是所有支路都失效。

两个构件可靠度为 `R1、R2` 时：

```text
R并 = 1 - (1-R1)(1-R2)
```

一般形式：

```text
R并 = 1 - Π(1-Ri)
```

例如两个模块可靠度都是 0.9：

```text
R并 = 1 - 0.1×0.1 = 0.99
```

这就是冗余提高可靠性的基本数学原因。

## 7. 混联系统

遇到串并联混合结构时，不要一次写大公式，按子结构逐层化简：

```text
先算一个并联系统的等效可靠度
        ↓
把它看成一个整体构件
        ↓
再与其他串联或并联部分继续计算
```

## 8. 故障率与指数可靠性模型

若题目假设故障率 `λ` 为常数，常见指数可靠度模型：

```text
R(t) = e^(-λt)
```

在这种模型下：

```text
MTTF = 1 / λ
```

这属于常见基础模型，考试一般给出足够条件或公式，不需要从概率论重新推导。

## 9. 可靠性设计常见思想

### 冗余

增加备用构件或重复信息，使局部故障不至于直接导致系统失效。

### 故障检测

尽快发现异常，例如心跳、超时、校验、自检。

### 故障隔离

把故障限制在局部，避免向其他模块传播。

### 恢复

故障发生后通过重启、切换、回滚、重试等方式恢复服务。

这些思想与[架构战术与质量属性实现](../10-系统质量属性与架构评估/02-架构战术与质量属性实现.md)中的可用性战术相互对应。

## 10. 主备与冗余

常见容错结构：

- 冷备：备用系统平时不运行，切换和恢复较慢；
- 温备：备用保持部分运行状态；
- 热备：备用系统实时或近实时保持可接管状态，切换较快。

一般来说，越接近热备，恢复时间越短，但资源和一致性维护成本也更高。

## 11. 可靠性测试与可靠性设计

可靠性设计关注如何通过架构和机制减少失效；可靠性测试关注通过运行和统计评价系统是否达到可靠性要求。

软件测试章节已经包含可靠性测试的基本位置，见[软件测试方法与分类](../05-软件工程基础/07-软件测试方法与分类.md)。

## 12. 做题固定判断

```text
串联系统：所有构件都正常才正常 → 可靠度相乘
并联系统：至少一个正常即可 → 1 - 所有支路同时失效的概率

可用性 = MTTF / (MTTF + MTTR)

想提高可用性：
少坏 → 提高MTTF
快修 → 降低MTTR
```

## 核心公式

```text
MTBF ≈ MTTF + MTTR

A = MTTF / (MTTF + MTTR)

R串 = ΠRi

R并 = 1 - Π(1-Ri)

常故障率模型：R(t)=e^(-λt)
MTTF=1/λ
```
