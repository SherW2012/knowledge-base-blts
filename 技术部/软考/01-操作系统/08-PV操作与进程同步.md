# PV操作与进程同步

## 1. 为什么会有 PV 操作

多个进程或线程并发执行时，如果它们会读写同一份共享数据，就可能出现执行顺序不同而结果不同的问题。进程同步要解决的核心是两件事：

1. **互斥**：同一时刻只允许一个执行者进入临界区；
2. **同步**：存在先后依赖时，让后续执行者等待前置条件满足。

信号量和 PV 操作就是教材中表达这两类约束的经典工具。

## 2. 信号量

信号量 `S` 是由操作系统维护的整数变量，只能通过原子操作 P 和 V 修改。

常见教材定义：

```text
P(S)：S = S - 1
      若 S < 0，则当前进程阻塞

V(S)：S = S + 1
      若 S <= 0，则唤醒一个等待进程
```

不同教材可能把 P/V 的判断顺序写成“先判断再减”或采用其他等价表示，做题时应以题目给出的定义为准。核心不变：**P 表示申请/等待，V 表示释放/通知。**

## 3. 用信号量实现互斥

若一个临界资源一次只能被一个进程使用，可设置：

```text
mutex = 1
```

进程进入临界区前执行：

```text
P(mutex)
```

离开临界区后执行：

```text
V(mutex)
```

完整结构：

```text
P(mutex)
    临界区
V(mutex)
```

为什么初值是 1？因为资源最开始有 1 个可用名额。第一个进程执行 P 后把名额占掉，其他进程再执行 P 就必须等待。

## 4. 用信号量实现前驱关系

如果要求“语句 A 执行完以后，语句 B 才能执行”，设置一个初值为 0 的同步信号量：

```text
S = 0

进程1：
A
V(S)

进程2：
P(S)
B
```

`S=0` 表示一开始条件尚未满足。进程2如果先运行，会在 `P(S)` 处等待；只有进程1完成 A 并执行 `V(S)`，B 才能继续。

因此判断初值时可以先问：

```text
这个信号量表示“资源数量”还是“事件是否已经发生”？
```

- 表示一个互斥资源：通常初值为 1；
- 表示一个尚未发生的前置事件：通常初值为 0；
- 表示 N 个同类可用资源：通常初值为 N。

## 5. 前趋图如何翻译成 PV 操作

前趋图中的一条边：

```text
A → B
```

表示 B 必须等待 A 完成。

可为这条依赖建立一个信号量 `S1=0`：

```text
A 后：V(S1)
B 前：P(S1)
```

若：

```text
A → C
B → C
```

C 需要同时等待 A、B，因此应分别设置两个同步信号量：

```text
S1 = 0
S2 = 0

A 后：V(S1)
B 后：V(S2)

C 前：
P(S1)
P(S2)
```

一个节点有几条前驱边，就要确保对应的前置条件都被等待；一个节点有几条后继边，就要向相应后继发送完成通知。

## 6. 生产者—消费者

设缓冲区容量为 `N`：

```text
empty = N    // 空槽数量
full  = 0    // 已放入产品数量
mutex = 1    // 缓冲区互斥访问
```

生产者：

```text
P(empty)
P(mutex)
    放入产品
V(mutex)
V(full)
```

消费者：

```text
P(full)
P(mutex)
    取出产品
V(mutex)
V(empty)
```

这里有三种不同约束：

- `empty` 防止缓冲区满了还继续生产；
- `full` 防止缓冲区为空时仍然消费；
- `mutex` 防止两个执行者同时修改缓冲区内部状态。

## 7. P 操作顺序为什么重要

生产者通常先：

```text
P(empty)
P(mutex)
```

而不是先拿 `mutex` 再等 `empty`。

如果生产者先占有互斥锁，再因为缓冲区已满而等待空槽，消费者虽然能够产生空槽，却可能因为拿不到 `mutex` 而无法进入缓冲区，最终形成死锁。

因此考试中除了补 P/V 数量，还要看**等待资源的顺序是否可能形成循环等待**。

## 8. 信号量数值的含义

采用经典负值定义时：

- `S > 0`：当前还有 S 个可用资源；
- `S = 0`：没有空闲资源，但暂时没有额外等待者；
- `S < 0`：绝对值可以表示等待该信号量的进程数量。

例如 `S=-3`，可理解为已有 3 个进程在等待。

## 9. PV 操作与死锁

PV 操作本身并不会自动避免死锁。多个信号量如果申请顺序不一致，仍然可能出现：

```text
进程A：占有 S1，等待 S2
进程B：占有 S2，等待 S1
```

这与[进程死锁与资源分配](04-进程死锁与资源分配.md)中的循环等待完全一致。

## 10. 做题固定步骤

看到前趋图或 PV 填空题时，按下面顺序：

1. 找出所有“必须先完成”的依赖边；
2. 每条独立依赖先理解成一个初值为 0 的事件信号量；
3. 前驱完成后 V；
4. 后继执行前 P；
5. 若还涉及共享资源，再单独增加互斥信号量；
6. 最后检查 P/V 顺序是否可能造成死锁。

## 核心关系

```text
P = 申请 / 等待
V = 释放 / 通知

互斥资源：初值通常为 1
N个同类资源：初值通常为 N
前置事件：初值通常为 0

A → B
等价于：A后V，B前P
```
