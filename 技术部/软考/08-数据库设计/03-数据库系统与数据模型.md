# 数据库系统与数据模型

## 1. 数据库系统的组成

**数据库（Database，DB）**是按一定结构组织并长期保存的数据集合。**数据库管理系统（DBMS）**是管理这些数据的软件，负责定义、查询、更新、权限、并发和恢复。数据库、DBMS、应用程序、用户及运行环境合起来构成**数据库系统（DBS）**。

```text
数据库系统 = 数据库 + DBMS + 应用程序 + 用户 + 运行环境
```

应用程序通常不直接修改数据库文件，而是向DBMS提交SQL或数据库API调用。DBMS解释请求，选择访问路径，执行读写并维护约束和事务。

## 2. DBMS的主要功能

| 功能 | 解决的问题 |
|---|---|
| 数据定义 | 建立表、字段、约束、视图和索引 |
| 数据操纵 | 查询、插入、修改和删除数据 |
| 数据控制 | 权限、完整性、并发和审计 |
| 事务管理 | 让一组操作作为一个工作单元提交或回滚 |
| 存储管理 | 管理数据页、文件、缓冲区和访问路径 |
| 故障恢复 | 根据日志和备份恢复到一致状态 |

数据库管理员（DBA）负责数据库规划、权限、备份恢复、容量和性能等管理工作；应用开发者主要使用DBMS提供的数据定义和访问能力。

## 3. 数据模型的三个层面

数据模型不是某个具体数据库产品，而是描述数据结构、数据联系、允许的操作和约束规则的一套方法。

- **概念数据模型**：从业务角度表达实体、属性和联系，典型工具是ER模型；
- **逻辑数据模型**：规定DBMS向用户提供的逻辑结构，例如关系、文档、图；
- **物理数据模型**：规定数据页、文件、索引和分区等存储方式。

这三个层面与[数据库三级模式](01-数据库三级模式.md)有关但不完全等同：数据模型强调“怎样描述数据”，三级模式强调“用户视图、全局逻辑结构和物理存储如何分层”。

## 4. 常见逻辑数据模型

### 4.1 层次模型

用树组织数据，每个子结点通常只有一个父结点。父子关系明确、路径访问直接，但难以自然表达多对多关系。

### 4.2 网状模型

用记录和链接形成网状结构，一个记录可以有多个父记录。表达联系比层次模型灵活，但应用依赖访问路径，结构复杂。

### 4.3 关系模型

用关系表达数据。工程实现通常呈现为表、行和列，并使用键、完整性约束和关系运算。

关系模型把逻辑操作建立在关系整体之上，应用不必沿着预先规定的物理指针逐条导航。这种逻辑独立性和统一查询能力是其长期占据主流的重要原因。

### 4.4 非关系模型

非关系数据库根据主要数据形态分为键值、文档、列族和图数据库等类型。它们不是一种统一模型，也不等于“没有结构”或“不支持事务”。

## 5. 数据库模式与数据库实例

- **模式（Schema）**：数据库结构的定义，例如有哪些表、字段和约束，变化相对较少；
- **实例（Instance）**：某一时刻数据库中实际保存的数据，会随着插入、修改和删除而变化。

`CREATE TABLE`主要改变模式，`INSERT`主要改变实例。考试中“型”与“值”“模式”与“实例”经常以这种静态定义和动态内容的区别出现。

## 核心关系

```text
现实世界 → 概念模型 → 逻辑数据模型 → DBMS内部物理结构
                         ├─ 关系模型
                         ├─ 文档模型
                         ├─ 键值模型
                         ├─ 列族模型
                         └─ 图模型
```
