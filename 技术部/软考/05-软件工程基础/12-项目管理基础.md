# 项目管理基础

## 1. 软件项目管理在管什么

项目管理不是只管“按时做完”，而是在范围、进度、成本、质量、资源和风险等约束之间做协调。

软考常见考点主要集中在：

- 工作分解与范围；
- 进度网络图、关键路径、PERT；
- 成本与挣值基础；
- 风险管理；
- 配置管理与变更控制。

## 2. 范围管理与 WBS

项目范围说明项目要交付什么、不交付什么。

WBS（Work Breakdown Structure，工作分解结构）把项目逐层分解为更小、可管理的工作包。

```text
项目
├── 子系统A
│   ├── 工作包A1
│   └── 工作包A2
└── 子系统B
    ├── 工作包B1
    └── 工作包B2
```

WBS 的核心是**按可交付成果或工作范围逐层分解**，直到能够估算、安排、分配和跟踪。

范围蔓延指未经正式控制不断加入新需求，最终导致进度和成本失控。

## 3. 活动网络与关键路径

项目活动之间可能存在前后依赖。网络图用于表示这些依赖，并计算项目最短完成时间。

**关键路径**是网络图中总持续时间最长的路径。

关键路径上的活动通常：

```text
总时差 = 0
```

其中任一关键活动延期，如果没有采取补救措施，项目总工期也会延期。

### 计算步骤

1. 正向计算每个活动的最早开始和最早完成时间；
2. 得到项目最早完成时间；
3. 反向计算最迟开始和最迟完成时间；
4. 计算时差；
5. 时差为 0 的连续活动构成关键路径。

## 4. 总时差

常见关系：

```text
总时差 = 最迟开始时间 - 最早开始时间
       = 最迟完成时间 - 最早完成时间
```

总时差表示在不影响项目总工期的前提下，一个活动最多可以推迟多少时间。

关键活动的总时差通常为 0。

## 5. PERT 三点估算

当活动时间存在较大不确定性时，PERT 常使用三点估算：

- `a`：乐观时间；
- `m`：最可能时间；
- `b`：悲观时间。

期望时间：

```text
te = (a + 4m + b) / 6
```

方差：

```text
σ² = ((b - a) / 6)²
```

标准差：

```text
σ = (b - a) / 6
```

考试中最常考的是期望时间公式。

## 6. 赶工与快速跟进

项目需要压缩进度时，常见两种办法：

### 赶工 Crashing

增加资源或成本来缩短关键活动时间。

例如增加人员、使用更高成本设备、外包部分工作。

### 快速跟进 Fast Tracking

把原本顺序执行的活动部分并行执行。

它可能缩短时间，但通常会增加返工和协调风险。

只有压缩**关键路径上的活动**才一定可能缩短项目总工期；压缩非关键活动，如果其时差仍未用完，项目总工期可能不变。

## 7. 风险管理

风险是未来可能发生、会对项目目标产生影响的不确定事件。

典型过程：

```text
风险识别
  ↓
风险分析
  ↓
制定应对计划
  ↓
监控风险
```

常用风险评价思路：

```text
风险暴露度 = 风险发生概率 × 风险损失
```

### 常见应对策略

- **规避**：改变方案，使风险不再存在；
- **转移**：把影响或责任转移给第三方，例如保险、外包；
- **减轻**：降低概率或损失；
- **接受**：认可风险存在，必要时准备应急措施。

## 8. 软件配置管理

配置管理负责对软件生命周期中的重要工作产品建立标识、版本和受控变更。

配置项可以包括：

- 需求文档；
- 设计文档；
- 源代码；
- 测试用例；
- 构建脚本；
- 配置文件等。

典型活动：

- 配置标识；
- 版本控制；
- 变更控制；
- 配置状态记录；
- 配置审计。

## 9. 基线与变更控制

基线是经过正式评审批准、后续修改必须受控的版本。

变更流程通常是：

```text
提出变更
  ↓
分析影响
  ↓
变更控制机构审批
  ↓
修改配置项
  ↓
验证并更新基线/版本记录
```

CCB（Change Control Board，变更控制委员会）负责评估和批准重要变更，但它不是“亲自编写代码的开发小组”。

## 10. 成本与挣值基本量

挣值管理把范围、进度和成本放到同一套指标中。

常见三个基本量：

- **PV**：计划价值，按计划到当前应该完成多少工作对应的预算；
- **EV**：挣值，实际已经完成的工作按预算值计算；
- **AC**：实际成本，实际为已完成工作花了多少钱。

常见差异：

```text
进度偏差 SV = EV - PV
成本偏差 CV = EV - AC
```

判断：

```text
SV > 0：进度超前
SV < 0：进度落后

CV > 0：成本节约
CV < 0：成本超支
```

常见绩效指数：

```text
SPI = EV / PV
CPI = EV / AC
```

大于 1 一般表示表现优于计划，小于 1 表示表现差于计划。

## 11. 质量管理

项目质量管理既包括对产品结果的检查，也包括通过过程和方法减少缺陷产生。

可以区分：

- **质量保证**：关注过程是否能够持续产生符合要求的结果；
- **质量控制**：通过检查、测试、度量等发现具体结果中的问题。

## 12. 做题快速判断

```text
最长路径 → 关键路径
关键活动 → 总时差通常为0
三点估算 → (a + 4m + b) / 6
只压缩非关键活动 → 不一定缩短总工期

EV - PV → 进度偏差
EV - AC → 成本偏差

未经批准不断加需求 → 范围蔓延
批准后的受控版本 → 基线
审批重要配置变更 → CCB
```

## 核心关系

```text
项目管理
= 范围 + 进度 + 成本 + 质量 + 风险 + 配置/变更

关键路径决定项目最短工期
风险管理处理“不确定的未来事件”
配置管理保证软件工作产品的版本和变更可控
```
