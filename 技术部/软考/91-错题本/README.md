## 复盘格式与掌握状态

每道错题解析必须就地展示完整原题、所有选项、必要的共享材料，再列个人答案、正确答案、推理过程、各干扰项的错误原因及对应知识链接。不能仅写题号后要求翻回试卷。

记录状态分为“答错待复测”“答对但靠猜／理由不确定”“已讲解待复测”“迁移复测通过”。答对不直接等同于掌握；只有能够解释依据并通过改变条件或任务的复测，才更新掌握状态。主观错因没有证据时记录为待确认，不能凭答案排列推断作答动机。

复测保留原题记录，另附新题及结果，不能覆盖初次作答历史。新卷与复盘分开，作答阶段仅展示试题；批改时再展示相应答案和解析。

## 出题约束

- 模拟卷默认包含综合知识、案例分析与论文；“先做选择题”只表示作答顺序，不据此省略其他部分。
- 选择题选项仅以A、B、C、D标识，每项单独一行，不使用带圆点的列表。

1. 覆盖计算机基础、操作系统、网络、数据库、软件工程、UML与模式、架构设计与评估、可靠性、安全、云与分布式、嵌入式、数据处理、项目管理和专业英语。以具体考试资格为主线，不混称“信息系统项目管理师”和“系统架构设计师”。
2. 案例不限于当前职业、公司或某个TPS系统。采用跨行业通用场景；不把工作经历当作技术范围边界。
3. 出题前对照可检索的历史试卷与本模块。原题复用必须有明确复测目的并标注；仅替换数值、实体名称、背景故事或选项位置，不算新题。历史材料不全时不声称完成全历史去重。
4. 本轮避开已多次出现的流水线时间、页表容量、LRU访问序列、DFD父子图平衡、质量属性场景六要素识别，以及直接提供圈复杂度公式后的代入算术。
5. ABSD的三个需求来源、三项基础、六阶段，以及与ABSDM和GoF模板方法的简单名词区别，已有反复练习记录，避免再次机械考查。
6. 同一知识点再次出现时，改变所需推理：边界、失败条件、反例、约束变化或方案取舍。错题知识点可以迁移复测，但不能继续复用原有题干结构。
7. 干扰项应属于相邻概念或真实可考虑的方案，并对应具体误解。控制送分题数量，不用三个与题干完全无关的选项制造掌握假象。
8. 计算题需考查建模、条件识别或结果解释。常见基础公式不直接写进题干后要求机械代入。
9. 每道单选题应有唯一最合适答案，交代必要假设；检查多解、版本差异、隐含条件和选项长度提示。答案位置应充分打散，不采用循环序列。
10. 归档保存题号、题干、选项与试卷标识，后续去重比较考查机制与推理路径，不只匹配关键词。
