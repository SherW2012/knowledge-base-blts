# 创意池

用于集中记录尚处于观察、验证和发散阶段的创意。零散点子优先追加在这里，不必每个点子单独建立 Markdown 文件；当某个方向逐渐形成完整研究、项目或方法论后，再单独拆分。

---

## 2026-08-25｜7 个 GitHub 上最值得看的 AI 赚钱项目

### 1. MakeMoneyWithAI

https://github.com/garylab/MakeMoneyWithAI

AI 赚钱项目百科全书。现在已经整理到 389 个能用 AI 做产品、自动化和变现的开源项目。

从社交媒体监听、趋势情报到内容采编，每条路径都给你标好了赚钱方向。收藏一个，等于一次性拿走 389 个机会。

创意方向：可以把它当成“AI 变现机会池”的上游数据源，未来让 Agent 定期扫描新增项目，自动分析商业模式、复制门槛和潜在收益。

### 2. Agent-Reach

https://github.com/Panniantong/Agent-Reach

给 AI Agent 装上全网眼睛。Twitter、Reddit、YouTube、GitHub、B 站、小红书等平台一键读取，零 API 费用，自愈路由。

以前 Agent 被关在笼子里，现在直接打开整个互联网。找热点、做情报、挖机会都更快。

创意方向：用 Agent-Reach 做自动需求发现器，从全网持续寻找热点、用户吐槽、未满足需求、低粉爆款和潜在产品机会。

### 3. MoneyPrinterTurbo

https://github.com/harry0703/MoneyPrinterTurbo

AI 一键生成短视频。

短视频自动化生产仍然是最直接的 AI 应用之一。内容不一定要靠灵感，可以把选题、文案、配音、素材、剪辑、输出逐步做成自动生产线。

创意方向：把它作为“无人内容工厂”的参考实现，研究如何进一步接入自动选题、热点判断、账号分发和变现闭环。

### 4. MarkItDown

https://github.com/microsoft/markitdown

微软开源的文档预处理工具。PDF / Word / PPT / Excel / 音视频等内容可以统一转换成适合 LLM 处理的 Markdown。

以前整理资料还要自己清洗，现在可以直接交给工具处理，适合知识库、RAG、资料分析等场景。

创意方向：任何资料型生意都可以尝试接入 MarkItDown：原始文件 → Markdown → LLM → 结构化信息 → Agent → 最终产品。

### 5. ClawWork

https://github.com/HKUDS/ClawWork

AI 打工经济测试框架。重点不是“AI 真到账两万美元”，而是开始用真实职业任务测试 Agent 到底能创造多少经济价值。

它提供了一个值得长期关注的方向：不只 benchmark 模型有多聪明，而是 benchmark 一个 Agent 能创造多少美元价值。

创意方向：做 Agent 收益率排行榜，把模型成本、完成任务价值、成功率、耗时、人工介入时间统一换算成 ROI，寻找真正具备经济价值的 Agent 工作流。

### 6. goose

https://github.com/block/goose

开源 AI 程序员。给一句需求就能搭项目、装依赖、写代码、跑测试，并支持多种 LLM 和本地模型。

以前一些小工具需要花钱找开发，现在越来越多需求可以直接由 Agent 完成，降低开发费用和沟通成本。

创意方向：把 goose 作为自动赚钱系统中的“执行员工”，在需求发现和商业判断之后，自动完成产品开发、测试和迭代。

### 7. superpowers

https://github.com/obra/superpowers

把需求分析、测试、调试、代码审查等软件开发流程 Skill 化。

重点不是单纯让 AI 写代码，而是把成熟程序员的工作方法塞进 Agent，让它按照一套稳定的软件工程流程工作。

创意方向：作为未来 Agent Harness 的“工作制度”，解决谁负责需求、设计、测试、调试、Code Review 和验收的问题。

## 可以拼成的一条完整链路

这 7 个项目并不是孤立的，可以继续组合成一条 AI 自动赚钱流水线：

MakeMoneyWithAI → 找现成商业模式和机会

Agent-Reach → 全网发现真实需求和热点

MarkItDown → 清洗并结构化外部资料

ClawWork → 判断任务的经济价值和 ROI

goose → 自动开发产品

superpowers → 给开发 Agent 加上需求、测试、调试、Review 和验收流程

MoneyPrinterTurbo → 作为内容类产品自动生产线的参考实现

最终可以继续验证一个更大的方向：

需求发现 Agent → 商业判断 Agent → 产品开发 Agent → 测试验收 Agent → 自动上线 → 收益验证。
