# 创意池

用于集中记录尚处于观察、验证和发散阶段的创意。零散点子优先追加在这里，不必每个点子单独建立 Markdown 文件；当某个方向逐渐形成完整研究、项目或方法论后，再单独拆分。

## 2026-08-25｜7 个 GitHub 上最值得看的 AI 赚钱项目

### 1. MakeMoneyWithAI

https://github.com/garylab/MakeMoneyWithAI

AI 赚钱项目百科全书。现在已经整理到 389 个能用 AI 做产品、自动化和变现的开源项目。

从社交媒体监听、趋势情报到内容采编，每条路径都给你标好了赚钱方向。收藏一个，等于一次性拿走 389 个机会。

创意方向：可以把它当成“AI 变现机会池”的上游数据源，未来让 Agent 定期扫描新增项目，自动分析商业模式、复制门槛和潜在收益。

### 2. Agent-Reach

https://github.com/Panniantong/Agent-Reach

给 AI Agent 装上全网眼睛。Twitter、Reddit、YouTube、GitHub、B 站、小红书等平台一键读取，零 API 费用，自愈路由。

以前 Agent 被关在笼子里，现在直接打开整个互联网。找热点、做情报、挖机会都更快。

创意方向：用 Agent-Reach 做自动需求发现器，从全网持续寻找热点、用户吐槽、未满足需求、低粉爆款和潜在产品机会。

### 3. MoneyPrinterTurbo

https://github.com/harry0703/MoneyPrinterTurbo

AI 一键生成短视频。

短视频自动化生产仍然是最直接的 AI 应用之一。内容不一定要靠灵感，可以把选题、文案、配音、素材、剪辑、输出逐步做成自动生产线。

创意方向：把它作为“无人内容工厂”的参考实现，研究如何进一步接入自动选题、热点判断、账号分发和变现闭环。

### 4. MarkItDown

https://github.com/microsoft/markitdown

微软开源的文档预处理工具。PDF / Word / PPT / Excel / 音视频等内容可以统一转换成适合 LLM 处理的 Markdown。

以前整理资料还要自己清洗，现在可以直接交给工具处理，适合知识库、RAG、资料分析等场景。

创意方向：任何资料型生意都可以尝试接入 MarkItDown：原始文件 → Markdown → LLM → 结构化信息 → Agent → 最终产品。

### 5. ClawWork

https://github.com/HKUDS/ClawWork

AI 打工经济测试框架。重点不是“AI 真到账两万美元”，而是开始用真实职业任务测试 Agent 到底能创造多少经济价值。

它提供了一个值得长期关注的方向：不只 benchmark 模型有多聪明，而是 benchmark 一个 Agent 能创造多少美元价值。

创意方向：做 Agent 收益率排行榜，把模型成本、完成任务价值、成功率、耗时、人工介入时间统一换算成 ROI，寻找真正具备经济价值的 Agent 工作流。

### 6. goose

https://github.com/block/goose

开源 AI 程序员。给一句需求就能搭项目、装依赖、写代码、跑测试，并支持多种 LLM 和本地模型。

以前一些小工具需要花钱找开发，现在越来越多需求可以直接由 Agent 完成，降低开发费用和沟通成本。

创意方向：把 goose 作为自动赚钱系统中的“执行员工”，在需求发现和商业判断之后，自动完成产品开发、测试和迭代。

### 7. superpowers

https://github.com/obra/superpowers

把需求分析、测试、调试、代码审查等软件开发流程 Skill 化。

重点不是单纯让 AI 写代码，而是把成熟程序员的工作方法塞进 Agent，让它按照一套稳定的软件工程流程工作。

创意方向：作为未来 Agent Harness 的“工作制度”，解决谁负责需求、设计、测试、调试、Code Review 和验收的问题。

## 可以拼成的一条完整链路

这 7 个项目并不是孤立的，可以继续组合成一条 AI 自动赚钱流水线：

MakeMoneyWithAI → 找现成商业模式和机会

Agent-Reach → 全网发现真实需求和热点

MarkItDown → 清洗并结构化外部资料

ClawWork → 判断任务的经济价值和 ROI

goose → 自动开发产品

superpowers → 给开发 Agent 加上需求、测试、调试、Review 和验收流程

MoneyPrinterTurbo → 作为内容类产品自动生产线的参考实现

最终可以继续验证一个更大的方向：

需求发现 Agent → 商业判断 Agent → 产品开发 Agent → 测试验收 Agent → 自动上线 → 收益验证。

## 2026-08-25｜AI Agent 公司化：一个人拥有一支 AI 团队

这一轮项目与上一轮最大的区别，是关注点从“AI 帮我完成一个任务”继续向“AI 组成一个组织”推进。

真正值得观察的不是某个单独 Agent，而是一个人如何逐渐拥有完整的虚拟公司：有岗位、有记忆、有管理层、有数据入口、有工作制度，也有可以直接交付的生产部门。

### 1. Agency Agents

https://github.com/msitarzewski/agency-agents

集合大量专业 AI Agent，覆盖开发、设计、产品、营销等不同岗位。

创意方向：把 Agent 从“通用助手”升级为“虚拟员工”。未来的一人公司可以由真人负责 CEO、客户关系和关键决策，其余工作拆成产品、研发、设计、营销、运营等 Agent 岗位。

它可以被理解为 AI 公司的“人力资源部 / 岗位模板库”。

### 2. Codebase Memory MCP

https://github.com/DeusData/codebase-memory-mcp

把代码库转换为 AI 更容易理解和查询的知识结构，让 Agent 在长期项目中持续理解代码关系，而不是每次工作都从头重新读取上下文。

创意方向：给长期工作的 AI 员工建立“组织记忆”。真正可持续的 Agent 系统不能只有当前 Context，还需要项目级长期记忆：代码结构、历史决策、模块关系、踩坑记录和已经完成的工作都应该能够被后续 Agent 复用。

可以形成：短期上下文 → 项目记忆 → 长期知识图谱。

### 3. Agent-Reach

https://github.com/Panniantong/Agent-Reach

已在上一条创意中记录，不重复展开。

在“AI Agent 公司”视角下，它更适合作为公司的外部情报部门：主动读取 X、Reddit、YouTube、GitHub、小红书等平台，持续寻找市场变化、热点、用户需求和赚钱机会。

### 4. OpenMontage

https://github.com/calesthio/OpenMontage

让 AI Agent 参与内容生产，从选题、脚本、素材到剪辑和渲染逐步自动化。

创意方向：把自媒体生产从“一个 AI 视频工具”继续升级成“AI 内容部门”。

可以拆成：选题 Agent → 编剧 Agent → 素材 Agent → 剪辑 Agent → 渲染与发布。

它更值得参考的不是某个视频功能，而是如何模拟一个小型 MCN 的内容生产组织。

### 5. Orca

https://github.com/stablyai/orca

多 Agent 协作和并行任务方向的项目。

创意方向：当 Agent 数量增加以后，真正的问题不再只是“AI 能不能做”，而是“这么多 AI 谁来管”。

未来的 Harness 需要承担类似管理层的职责：任务拆分、Agent 分配、并行执行、依赖关系、状态追踪、失败重试、结果汇总和最终验收。

它可以被理解为 AI 公司的“管理层 / 调度系统”。

### 6. Firecrawl

https://github.com/firecrawl/firecrawl

把网站内容抓取并转换成更适合 AI 使用的数据，是 Agent 获取互联网信息和构建 RAG、研究系统时的重要数据基础设施。

创意方向：作为 AI 公司的数据入口。

Agent-Reach 更像负责“去哪找信息”，Firecrawl 更像负责“找到网站以后，怎样把它变成 Agent 能吃的数据”。两者可以组成外部数据采集层。

## 总创意：AI Company OS

未来的一人公司，可能并不是“一个超级个体使用很多 AI 工具”，而是：

一个真人担任 CEO，下面运行着一整套有岗位、有记忆、有制度、有管理层、有数据源和生产部门的 AI Agent 公司。

可以逐渐拼成这样一套系统：

Agent-Reach / Firecrawl
→ 外部世界、市场情报、需求和数据获取

Codebase Memory / Knowledge Graph
→ 公司记忆、项目记忆和长期知识

Agency Agents
→ 虚拟员工与岗位体系

Orca
→ 多 Agent 组织、任务拆分和调度管理

superpowers
→ 工作制度、需求分析、测试、调试、Review 和验收方法

goose
→ 软件开发部门

OpenMontage / MoneyPrinterTurbo
→ 内容生产部门

MakeMoneyWithAI
→ 商业机会池

ClawWork
→ 经济价值评估与 Agent ROI

最终形成：

外部机会发现 → 数据采集 → 公司记忆 → 任务拆分 → Agent 分工 → 自动生产 → 自动验收 → 上线交付 → 收益验证。

值得继续验证的问题：

- 一个人是否真的可以管理几十个甚至上百个长期运行的 Agent 岗位？
- Agent 之间如何共享公司级长期记忆，而不造成 Context 和 Token 成本失控？
- 如何为每个 Agent 设置明确 KPI、成本和收益？
- 哪些岗位已经可以做到高比例自动化，哪些岗位仍然必须由真人掌握？
- 能否最终形成一套可复制的“一人公司操作系统 / AI Company OS”？
