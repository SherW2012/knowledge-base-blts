# 小红书未来优化思路

## 一、当前问题

现有小红书创作模板已经比较成熟，优点很明确：

- 结构稳定
- 合规规则完整
- 标题、封面、正文页、短文案都有固定输出规范
- 适合快速、批量、稳定地产出科技内容
- 已经形成统一视觉母版，执行成本低

但当前瓶颈也越来越明显：

**模板解决了“怎么稳定写出来”，但还没有解决“用户为什么愿意看、愿意滑、愿意收藏”。**

现有结构容易把不同类型的选题都写成同一种形态：

> 发生了什么 → 解释背景 → 讲功能 → 讲影响 → 总结

这种结构信息完整，但容易像科技媒体、公众号卡片或产品说明书。

对于小红书来说，信息本身不是全部。用户更关心的是：

- 这件事跟我有什么关系？
- 你有没有替我试过？
- 我看完能拿走什么？
- 这件事本身有没有冲突、意外、故事感？

未来优化的核心不是推翻旧模板，而是在旧模板之前增加一层：

**先判断“这条内容应该怎么讲”，再决定“用什么结构写”。**

旧模板继续保留，作为成熟的排版、合规和基础输出规范。

# 二、未来小红书内容必须优先回答的四个问题

## 1. 这东西和我有什么关系？

科技新闻不能只停留在“某公司发布了什么”。

用户真正会停下来的原因通常是：

- 它会不会改变我的工作？
- 它能不能帮我少做一步？
- 它会不会影响我正在用的工具？
- 它是不是我现在就能用？
- 它是不是意味着一种新的工作方式已经出现？

### 差的表达

> OpenAI 正在测试 Persistent Mode。

### 更适合小红书的表达

> 我电脑关了，AI 还能继续帮我干活？

新闻是证据，用户自己的生活和工作才是入口。

以后每个选题在写之前，都要先补一句：

> **这件事对普通用户、AI 工具用户、程序员、内容创作者或职场人，到底意味着什么？**

如果回答不出来，这条新闻大概率不适合直接做小红书。

---

## 2. 你替我试过了吗？

小红书不是纯资讯平台，用户天然更相信“有人替我用过、踩过、试过”。

所以以后不能只做：

> 产品介绍

更应该尽量做：

> 我实际怎么用
> 我拿它做了什么
> 哪一步好用
> 哪一步很蠢
> 哪些宣传说得太满
> 什么场景真的适合

### 例子

Wondering Canvas 不要只写：

> 一个支持并行对话的可视化学习工具。

更好的切口是：

> 我拿它学了一下午 DeepSeek Harness，终于知道这种“可视化聊天”到底适合干嘛了。

这里的“我”不是为了做人设，而是给用户一个真实的使用视角。

未来工具类内容优先增加：

- 实际截图
- 实际 Prompt
- 实际使用流程
- 使用前后对比
- 使用过程中出现的问题
- 真实结论，而不是产品宣传词

---

## 3. 给我一个能拿走的东西

小红书用户滑完以后，最好能留下一个明确的“可带走资产”。

可以是：

- 一个 Prompt
- 一个操作步骤
- 一张流程图
- 一份工具清单
- 一个网站
- 一套 Skill
- 一个 GitHub 项目
- 一个判断框架
- 一个对比结论
- 一套配置
- 一个可以直接复制的模板

这会直接提高内容的收藏价值。

以后写每篇内容前都要问：

> **用户看完这一篇，具体能拿走什么？**

如果答案只是“知道了一条新闻”，内容价值通常还不够。

### 示例

不要只写：

> Wondering Canvas 支持树状学习。

可以直接给：

> 我用它学习 DSH 的第一条 Prompt，直接复制：

然后给出实际 Prompt。

这类内容比再解释 300 字产品原理更有价值。

---

## 4. 有冲突、有意外、有故事

科技内容也需要叙事张力。

所谓故事，不是硬编剧情，而是找到真实存在的变化、冲突和认知落差。

常见的内容张力包括：

- 我原本以为 A，结果发现 B
- 大家都在做 A，但这个产品反着做 B
- 原本只能做到 A，现在已经做到 B
- 看起来只是一个小工具，实际背后是一个更大的变化
- 一个已经被大家默认的结论，被新信息推翻
- 一个很专业的能力，突然开始被普通人直接调用

### 示例

K-Dense Scientific Agent Skills 不要只写：

> 目前有 163 个科研 Skill。

可以写：

> 我本来只是想找几个 Agent Skill，结果翻进去发现连药物研发、基因组、实验室自动化都已经有人写好了。

同样的信息，因为有了认知落差，阅读感完全不同。

# 三、旧模板保留，但角色需要改变

现有 `00_小红书文案写作Prompt模板(1).md` 和 `小红书图文母版_更新版.html` 继续保留。

旧模板不废弃，未来主要负责：

- 合规检查
- 标题字数
- 封面规范
- 违禁词扫描
- 字数限制
- Tag 规范
- 基础排版
- 视觉统一
- 最终交付格式

但旧模板不再承担最核心的“叙事决策”。

未来完整流程应该变成：

> 情报进入
> ↓
> 判断用户为什么会在意
> ↓
> 判断有没有真实体验或验证空间
> ↓
> 设计用户能带走的东西
> ↓
> 找到冲突 / 意外 / 故事点
> ↓
> 选择合适叙事类型
> ↓
> 再进入旧模板完成标题、正文、排版和合规

也就是说：

**旧模板从“创作模板”逐渐变成“生产规范”。**

# 四、未来新增：小红书叙事引擎

不同选题不能再统一塞进一个五图结构。

未来至少拆成以下几种叙事类型。

## 类型 A：我替你试了

适合：

- AI 工具
- 网站
- App
- Agent
- Skill
- 新功能
- 工作流

结构建议：

> 我为什么去试
> ↓
> 我实际拿它做了什么
> ↓
> 哪个地方真的有用
> ↓
> 哪个地方还不好用
> ↓
> Prompt / 步骤 / 使用方法直接给用户

例子：

> 我用 Wondering Canvas 学了一下午 DSH

比：

> Wondering Canvas 是什么

更有小红书感。

---

## 类型 B：已经发展到这里了

适合：

- 前沿模型
- Agent 新能力
- AI 员工
- 自动化
- 机器人
- 新型交互方式

核心不是介绍参数，而是制造时间感：

> 原来大家还停留在 A，现在已经有人做到 B。

例子：

> AI 员工现在真的有自己的电脑了。

然后再讲产品和事实。

---

## 类型 C：一个具体问题

适合：

- Bug
- 使用问题
- 配置问题
- 常见误区
- 教程
- 搜索型内容

结构：

> 具体问题
> ↓
> 为什么发生
> ↓
> 怎么判断
> ↓
> 怎么处理
> ↓
> 哪些情况不适用

例子：

> Codex 为什么每次先 Reconnecting 5 次？

这种内容搜索价值和收藏价值都很高。

---

## 类型 D：我挖到一个宝藏

适合：

- GitHub 项目
- Skill 库
- Prompt 库
- 课程
- 数据集
- 网站集合
- 工具清单

核心不是介绍仓库 README，而是回答：

> 我为什么觉得它值得存
> ↓
> 里面最值得看的是什么
> ↓
> 谁适合用
> ↓
> 怎么直接开始

例子：

> 最近翻 GitHub 挖到一套 AI Engineer 实战课

正文直接列出：

- RAG
- Agent Loop
- MCP
- Skill
- Harness

以及怎么跑。

---

## 类型 E：认知反差 / 观点

适合：

- 行业趋势
- 新工作方式
- AI 创业
- Agent 生态
- 内容创作变化

结构：

> 一个真实观察
> ↓
> 为什么和原来的认知不一样
> ↓
> 给出 1-2 个事实
> ↓
> 留下判断

不需要写成行业报告。

---

## 类型 F：对比实验

适合：

- 模型对比
- 工具对比
- Prompt 对比
- 工作流对比
- 同一个任务不同 Agent 的差异

重点不只是“谁赢了”，而是：

- 我用什么任务测
- 实际输出有什么差别
- 哪种场景选谁
- 哪些结果出乎意料

这种内容天然适合截图、卡片和收藏。

---

# 五、图片结构也需要从“文章分页”改成“滑动叙事”

当前常见结构：

> 封面
> ↓
> 图2：大段正文
> ↓
> 图3：大段正文
> ↓
> 图4：大段正文
> ↓
> 图5：大段正文

未来不应该默认每张图承担 300 多字解释。

建议根据内容动态决定 3-7 张。

一个更适合小红书的通用结构可以是：

## 图1：封面

只回答：

> 为什么我要停下来点开？

---

## 图2：证据

放：

- 产品截图
- 新闻原图
- 实际运行结果
- 对话截图
- GitHub 页面
- 数据图

尽量少解释。

让用户先相信“这件事真的发生了”。

---

## 图3：最有意思的发现

只讲 1-3 个点。

不要铺满一页。

---

## 图4：可以直接拿走的东西

例如：

- Prompt
- 步骤
- 配置
- 清单
- 网址
- 方法

---

## 图5：真实评价 / 限制

告诉用户：

- 什么人适合
- 什么人没必要
- 哪些地方还不好用
- 当前有哪些限制

自然结束。

如果三张能说完，就不要硬凑五张。

---

# 六、选题进入创作前增加“叙事判断”

以后每条情报进入小红书创作部门前，先进行一次快速判断。

## 选题检查表

### 1. 用户关系

这件事和哪类用户有直接关系？

- 普通 AI 用户
- 程序员
- 职场人
- 学生
- 内容创作者
- 自由职业者
- 创业者
- 摄影 / 设计 / 视频用户

如果只能回答“AI 从业者会关注”，需要继续缩小场景。

### 2. 体验空间

能不能亲自：

- 打开
- 安装
- 跑一次
- 问一次
- 对比一次
- 截一次图

如果能，优先做体验型内容。

### 3. 可带走资产

用户能拿走什么？

至少明确一个。

### 4. 故事点

有没有：

- 认知反差
- 意外结果
- 冲突
- 变化
- 失败
- 踩坑
- 反常识

### 5. 叙事类型

最终标记：

- 我替你试了
- 已经发展到这里了
- 一个具体问题
- 我挖到一个宝藏
- 认知反差 / 观点
- 对比实验

然后再开始写。

# 七、减少“科技媒体腔”

以后小红书创作需要主动减少以下表达：

- 某公司发布某产品
- 该功能支持……
- 这意味着……
- 未来有望……
- 值得关注的是……
- 从行业角度来看……
- 进一步来看……

这些表达本身不一定错，但连续出现会让账号变成资讯搬运号。

更鼓励使用：

- 我刚试了一下
- 我原本以为……
- 真正让我觉得有意思的是……
- 我拿它做了一个具体任务
- 这里有个地方和我想的不一样
- 如果你平时会做 X，这个可能比较有用
- 这个 Prompt 我直接放出来
- 目前我觉得它最大的问题是……

前提是内容真实，不虚构体验。

---

# 八、从“信息密度”升级到“内容价值密度”

以前我们容易追求：

> 每张图塞更多信息。

未来更应该追求：

> 每滑一张，用户都得到一个明确的新东西。

一张图只要做到其中一项就够了：

- 一个意外
- 一个事实
- 一个截图
- 一个方法
- 一个 Prompt
- 一个结论
- 一个对比

不需要每页都写成完整文章。

---

# 九、未来的小红书内容生产流程

建议新的标准流程：

## Step 1：情报筛选

情报雷达负责发现：

- 新闻
- 工具
- GitHub
- Skill
- 模型
- 工作流
- 应用场景

## Step 2：小红书价值判断

回答四个问题：

1. 这东西和我有什么关系？
2. 你替我试过了吗？
3. 给我一个能拿走的东西。
4. 有冲突、有意外、有故事吗？

## Step 3：选择叙事类型

从六种类型中选择一个主叙事。

## Step 4：补真实素材

优先寻找：

- 实际截图
- 原始产品界面
- GitHub
- 实测结果
- Prompt
- 对比

## Step 5：设计图片顺序

先设计“用户每滑一张得到什么”，再写文字。

## Step 6：进入旧模板

调用旧 Prompt 完成：

- 合规
- 标题
- 文案
- 字数
- 标签
- 母版输出

## Step 7：发布后复盘

记录：

- 曝光
- 点击
- 点赞
- 收藏
- 评论
- 哪一页用户反馈最多
- 哪类叙事效果更好

长期建立自己的“小红书叙事数据集”。

# 十、未来目标

小红书创作部门不再只是：

> 把 AI 新闻改写成小红书图文。

而是逐渐变成：

> **把前沿情报重新加工成用户愿意看、愿意信、愿意收藏、愿意拿去用的内容。**

未来判断一篇内容好不好，不只看：

- 信息是否完整
- 文案是否合规
- 图片是否统一

还要看：

- 用户有没有代入感
- 有没有真实体验
- 有没有可复制价值
- 有没有阅读张力
- 有没有属于账号自己的判断

旧模板继续作为成熟生产底座。

新的优化方向，是在它上面再加一层真正的小红书叙事能力。
