# X 情报雷达与选题来源

> 本文档只服务于 X（Twitter）选题与情报获取。
> 
> 以后前沿部为 X 产品部寻找选题、扫描 AI 前沿信息、判断是否值得发帖，优先按照本文档的思路执行。
> 
> **小红书的信息源、选题逻辑与内容模型单独探索，不直接套用本体系。**

---

## 一、核心目标

X 情报雷达不是“搜 AI 新闻”，而是建立一套持续发现高价值信号的机制：

**发现信号 → 找到原始信源 → 交叉验证 → 必要时亲自测试 → 判断 X 传播价值 → 进入选题池 → 输出帖子**

X 更强调：

- 快
- 新
- 信息差
- 原始信源
- 圈内讨论度
- 明确观点
- 能引发回复、引用和争论

所以不能只等中文媒体整理好的二手新闻。

---

## 二、信息源分层

### 第一层：一手信源｜最高优先级

作用：确认事情到底是不是真的，并尽可能抢到最早的信息。

重点包括：

- OpenAI / Anthropic / Google DeepMind / Meta / xAI 等官方博客
- AI 公司官方 X 账号
- 创始人、CEO、核心研究员、核心工程师的个人 X
- GitHub 官方仓库
- GitHub Release / Commit / Issues / Discussions
- Hugging Face 模型页
- arXiv / 技术论文
- 产品官方 Changelog / Documentation

原则：

**任何爆炸性信息，只要条件允许，都尽量倒查到一手信源。**

二手媒体负责“发现”，一手信源负责“确认”。

---

### 第二层：黄金情报聚合源｜每天扫描

作用：降低寻找新闻和异常信号的成本。

重点渠道：

- AI HOT
- Hacker News
- Reddit
- Product Hunt
- GitHub Trending
- Hugging Face Trending
- Papers with Code
- 高质量 AI Newsletter

这一层不一定直接作为最终信源，主要回答一个问题：

> **今天有什么东西值得继续往下挖？**

发现有价值的信息后，再向第一层倒查。

---

### 第三层：开发者地下情报站

作用：寻找“官方还没正式宣传，但开发者已经开始讨论”的信息。

重点渠道：

- Linux DO
- V2EX
- GitHub Issues
- GitHub Discussions
- Hacker News 评论区
- Reddit 技术社区
- Discord 开发者社区
- Telegram 技术群 / 频道

重点寻找：

- 新工具
- 新模型真实体验
- API 变化
- 价格变化
- 隐藏功能
- Bug
- 模型偷偷更新
- Prompt / Workflow 新玩法
- Agent 新玩法
- AI Coding 新工具
- 薅羊毛信息
- AI 变现方式
- 开发者实际踩坑

这一层尤其适合寻找 X 上有讨论价值、但还没有被大众媒体报道的内容。

---

### 第四层：X 原生情报网｜核心资产

X 本身就是最重要的信息源之一。

不要只依赖 Home Timeline，重点建设不同主题的 X List。

建议长期维护：

#### AI Research

研究员、论文作者、大模型技术人员。

#### AI Coding

Cursor、Claude Code、Codex、Windsurf、Cline、OpenCode 等 AI Coding 方向的创始人、工程师和重度用户。

#### AI Founder

AI 公司创始人、CEO、独立开发者。

#### AI Agent

Agent、MCP、Memory、RAG、Multi-Agent、Computer Use 等方向开发者。

#### AI Money

AI SaaS、独立开发、AI 自动化、AI 获客、AI 变现、一人公司。

#### AI Tools

长期亲自测试各种 AI 产品和工具的人。

#### AI Commentary

擅长快速解读行业变化、提出有传播力观点的人。

日常获取情报时：

**优先扫 List，而不是无目的刷 Timeline。**

目标是逐渐形成自己的 X 信息源资产，而不是长期依赖算法推荐。

---

### 第五层：GitHub 雷达

GitHub 不只是代码仓库，也是极重要的 AI 前沿雷达。

重点关注：

- GitHub Trending
- Star 增速
- Fork 增速
- Release
- 最近 Commit
- Issues
- Discussions
- 新出现的 AI Repo
- 短时间快速增长的开源项目

重点寻找这种机会：

> **GitHub 已经爆了，但中文圈甚至 X 大多数人还没有开始讲。**

这类时间差非常适合抢首发。

不要只看项目总 Star 数，更要关注：

**增长速度。**

例如一个项目一天突然增加几千 Star，本身就是值得调查的异常信号。

---

### 第六层：中文 X 大佬 / 对标账号

中文 X、中文 AI 博主、对标账号可以看，但定位必须明确：

**它们主要是“选题雷达”，不是最终信源。**

重点观察：

- 什么题突然火了
- 什么标题容易获得点击
- 什么观点引发大量回复
- 评论区真正关心什么
- 什么角度最容易传播
- 有没有原作者没讲透的地方
- 有没有可以进一步实测、验证、补充的信息

正确流程：

**看到中文爆款 → 找到原始英文信源 → 自己验证 → 必要时自己测试 → 形成新的观点 → 再发。**

禁止简单换词搬运。

二创的价值必须来自：

- 新信息
- 新验证
- 新测试
- 新解释
- 新观点
- 新角度

## 三、X 情报漏斗

以后 X 产品部获取情报，默认按照下面的漏斗执行：

### Step 1：扫描

扫描：

**AI HOT / X Lists / Reddit / Linux DO / V2EX / GitHub / Hacker News / Product Hunt**

找到异常信号。

### Step 2：倒查

回到：

**官方博客 / 官方 X / GitHub / 论文 / 原作者**

确认事实。

### Step 3：补充上下文

弄清楚：

- 这件事为什么发生
- 和之前什么事情有关
- 对谁有影响
- 圈内为什么正在讨论
- 有没有争议

### Step 4：能实测就实测

尤其是：

- AI 工具
- 新模型
- AI Coding
- Agent
- Prompt
- Workflow
- 新功能

能自己跑一遍，就不要只复述别人。

### Step 5：判断 X 传播价值

一个候选选题至少检查：

1. **新不新？**
2. **有没有信息差？**
3. **有没有明确观点？**
4. **有没有反常识 / 冲突 / 反转？**
5. **有没有可以直接截图或展示的证据？**
6. **AI 圈的人会不会想回复？**
7. **有没有可能引发引用转发或讨论？**
8. **是不是已经被所有人讲烂了？**

如果只是“某公司今天发布了某功能”，但没有额外信息差和观点，优先级降低。

## 四、X 选题优先级

### S 级：立即跟

- 大模型突然发布
- AI 公司重大收购 / 合作 / 决裂
- 核心人物突然发表高争议观点
- AI Coding / Agent 出现明显范式变化
- 开源项目突然爆发增长
- 新模型出现明显反常识能力
- API / 定价 / 产品策略突然变化
- 圈内正在争论，但中文 X 还没有形成统一叙事

### A 级：值得做

- 新工具真实体验
- GitHub 新项目
- 新 Prompt / Workflow
- Agent 实践
- AI 变现案例
- 独立开发案例
- 开发者踩坑
- 新功能隐藏玩法
- 多模型横评

### B 级：需要重新找角度

- 普通模型升级
- Benchmark 新闻
- 公司例行公告
- 已被大量媒体报道的新闻
- 没有实测、没有观点、没有信息差的资讯

这类内容除非能找到新的冲突、数据、故事或观点，否则不优先发。

## 五、长期原则

### 1. X 优先追求“信号”，不是追求“完整”

不用等所有媒体都报道完再发。

只要事实已经可以确认，而且有足够价值，就可以快速形成第一版判断。

### 2. 越靠近信息源，价值越高

优先级大致为：

**本人 / 官方 / 原项目 > 开发者社区 > 专业媒体 > 聚合站 > 中文二创账号。**

### 3. 聚合站负责发现，不负责最终背书

AI HOT、Reddit、Linux DO、V2EX 等可以发现线索，但重要事实必须继续验证。

### 4. 不只看“新闻”，还要看“异常”

真正有价值的信号可能只是：

- 一个 GitHub Repo 突然暴涨
- 一个 CEO 连发三条 X
- 一个模型悄悄换了版本
- 一个 API 突然降价
- 一个 Issue 下面大量开发者抱怨
- 一个工具突然被大量独立开发者使用

这些都可能比正式新闻更值得做。

### 5. 先做自己的判断，再研究怎么写

情报获取和文案表达分开。

先回答：

> **这件事到底值不值得讲？**

再交给 X 产品部现有的文风、钩子、节奏和 A/B 测试体系处理。

## 六、与小红书体系的边界

本文档只定义 **X 的情报雷达与选题来源**。

不要默认把这一套完整复制到小红书。

原因是两个平台的传播逻辑不同：

- X 更吃前沿、速度、观点、圈内讨论和信息差
- 小红书更看重用户关系、实用价值、消费场景、封面点击与内容获得感

因此：

**X 情报雷达先独立运行。**

**小红书的信息源、选题池和筛选标准另行探索并单独沉淀。**
