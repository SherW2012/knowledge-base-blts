# X 情报雷达执行 Prompt

> **强制前置阅读。** 每次执行“今天 X 情报 / 过去一天 X 情报 / 更新 X 雷达 / 扫今天值得发的内容”前，完整读取本文档，并按本文档执行。不要凭记忆补规则，不要再叠加一份长手册。

## 0. 核心目标

目标不是寻找“最前沿、最高深、行业最重大”的 AI 新闻，而是寻找**普通人愿意点开、收藏、试一下、转给朋友的选题**。

优先级固定为：

**网感 + 传播性 + 利他性 > 技术深度 + 行业地位 + 资本规模。**

始终记住：

> **不要执着于那些高大上的高深莫测的最前沿技术理论，大部分人更关心今天晚上吃什么。**

每条候选先问一句：**读者看完能拿走什么？**

如果答案只是“知道某公司发生了一件大事”，通常不值得进主雷达。

## 1. 完整工作流

严格按下面顺序执行，不得漏步：

**确定 24h 窗口 → 扫多源 → 时间过滤 → 一手核验 → 去重聚类 → 评分筛选 → 生成当天 archive/report → 覆盖 latest.json → Push → 等 GitHub Actions 完整部署成功 → 最后亲自检查线上页面。**

具体要求：

1. **24h 窗口**：以北京时间为准，取 `[当前时间-24h, 当前时间]`，不是“昨天自然日”。
2. **扫多源**：按第 2、3 节执行。某源失败就记录 `partial/error`，不能拿别的媒体冒充已扫。
3. **时间过滤**：看原事件、原作者、官方发布的时间，不看二手媒体今天什么时候转述。旧闻再热通常不算今日新情报；但 **GitHub Trending 的“今天突然爆发”本身可以构成今日新事件**，不能因为仓库创建较早就直接过滤，需结合当日 Trending、当日涨星、传播突增等信号判断。
4. **一手核验**：重要事实尽量回到官方博客、官方 X、GitHub、原作者、产品页、论文原文确认。
5. **去重聚类**：同一事件在多个来源出现，只算一条；优先保留原始信源，其他来源做补充。
6. **评分筛选**：按第 4 节。宁缺毋滥，不为了凑数量塞生硬内容。
7. **生成数据**：写入 `radar-data/archive/YYYY-MM-DD.json` 和 `radar-data/reports/YYYY-MM-DD.md`。
8. **覆盖首页数据**：同步更新 `radar-data/latest.json`。只写 report 不改 latest，视为未完成。
9. **Push**：提交到仓库。
10. **等部署**：必须等 `Validate and publish knowledge base` 的 GitHub Actions 显示 `completed + success`。
11. **线上验收**：亲自检查网页日期、数量和首条内容确实已经变成当天数据。Commit 成功不等于网页更新成功。

## 2. 去哪里扫

### 第一优先级：GitHub Trending（头等重要）

**GitHub Trending 是主雷达最重要的发现源之一，每轮必须优先扫描，不得降级成辅助验证源。**

重点看：

- Daily Trending 里当天突然上升的 AI / Agent / Skill / Coding / 自动化 / 内容创作工具；
- 当日 `stars today`、24h 涨星或讨论量明显爆发的项目；
- 虽然仓库不是今天创建，但**今天第一次大规模进入视野**、今天突然爆发的项目；
- 免费、开源、本地可跑、无需注册、能直接安装或复制使用的项目；
- 一句话就能解释清楚，普通 AI 用户今天就能试的 Repo / Skill / Demo。

对 GitHub 项目，**不要把“仓库创建时间早”直接等同于“旧闻”**。如果今天进入 Daily Trending、当天涨星异常、被多人同时推荐，热度变化本身就是今日情报信号。

但也不能因为上了 Trending 就硬收：

- 太底层、太理论、需要长篇解释才知道有什么用的项目，仍然淘汰；
- 只对极少数基础设施开发者有意义、普通 AI 用户没有直接帮助的项目，仍然降权；
- GitHub 仓库不等于一定完全免费，若核心能力依赖收费 SaaS / API / 后端，必须核验并写清楚；优先选择有**真实免费或开源使用路径**的项目。

### 第二优先级：其他黄金发现源

继续从这些地方找“今天有什么值得继续挖”：

- **AI HOT**
- **Hacker News**
- **Reddit**
- **Product Hunt**
- **Hugging Face Trending**
- **Papers with Code**
- **高质量 AI Newsletter**

这些源主要负责**发现线索**，不是最终背书。

### 第三优先级：官方一手源

- OpenAI
- Anthropic
- Google DeepMind / Gemini
- Meta AI
- xAI
- 其他相关产品的官方博客、Changelog、GitHub、官方 X

主要负责**确认事实、补原始链接和准确时间**，不是为了每天硬找一条“公司大新闻”。

### 第四优先级：X 原生情报网 / 中文 X 大佬

这是长期核心资产，后续持续积累高信号账号和 Lists。

重点看：

- 谁在推荐一个刚冒头的 Skill / Repo / 工具；
- 哪个工作流突然被多人同时讨论；
- 哪条帖子评论区出现大量“我也在用 / 真有用 / 怎么装”；
- 中文 X 哪个选题突然跑起来，再回原始英文信源验证。

中文 X 用于**发现选题和传播角度**，不是拿来换词搬运。

## 3. 扫什么

优先寻找**普通人今天就能理解、接触、尝试、收藏或转发**的东西：

- **GitHub Trending / 开源项目**：优先免费、开源、可直接安装、可直接复制使用的 Repo。尤其关注当天突然爆发、涨星明显、中文圈还没讲烂的项目。简单实用优先于复杂先进。
- **Skill / 插件 / Prompt / 模板 / Workflow**：能直接拿走、安装、复制、复用。
- **Agent / Skill / Coding 工具**：可以推，但必须**简单、具体、有直接帮助**。例如少点几步、少写一段重复 Prompt、自动整理上下文、可视化 Agent 改了什么、把重复纠错沉淀成 Skill。若要先讲半天架构和理论才能理解价值，默认不推。
- **GitHub 小项目 / 开源工具 / Demo**：尤其是“刚出来、好玩、好用、中文圈还没讲烂”的项目。
- **学习资源**：已经帮用户排好顺序的课程、Repo、路线图、资料集合，比“再来 100 篇论文”更有价值。
- **AI Coding / Agent 的实际玩法**：必须能让用户明显省时间、少操作、做以前做不到的事；不要写对体验没变化的底层改动。
- **AI + 股票 / 币圈的新点子**：数据分析、研究、信息整理、监控、模拟、自动化等普通人能理解的结合方式；重点是新玩法，不是宏观金融新闻。
- **AI 赚钱 / 一人公司 / 副业**：内容、营销、获客、电商、自动化服务、数字产品、Skill/模板售卖、轻量 SaaS 等可复制案例。
- **价格 / 免费额度 / 新功能 / 新入口**：只有当用户能明显感知“更便宜、更方便、更强、更容易用”时才值得跟。
- **反常识、好玩、可展示的结果**：一张图、一段 Demo、一个链接就能让人产生“这我想试试”的冲动。

### 默认降权 / 不推荐

- 某高管离职、某公司融资、某公司收购谁、谁和谁达成资本合作。
- 某模型 / Agent 底层新增一个很深奥的能力，但用户体验没有明显提升。
- 某论文提出复杂理论，但普通用户没有可感知结果、可用 Demo 或可复制方法。
- 纯 benchmark、架构名词、行业宏大叙事、资本数字。
- GitHub Trending 上纯底层框架、复杂基础设施、深奥 Agent 架构，如果用户不能马上理解“它今天能帮我做什么”，不因为免费开源就强推。

除非它们**直接改变普通用户能做什么、花多少钱、怎么赚钱、怎么工作**，否则不进主雷达。

## 4. 评分与筛选

每条候选先过 3 个硬门槛：

1. **利他**：用户能拿走工具、方法、路径、机会、提醒或新玩法吗？
2. **可接触**：普通 AI 用户今天能理解或尝试吗？
3. **网感**：能不能用一句自然的话讲出“为什么我现在就想点开”？

三项里有两项答不上来，直接淘汰。

保留现有评分字段，但重新定义权重：

- `practicality`：35% —— 实用、可复制、可马上尝试
- `socialPotential`：30% —— 点击、收藏、转发、讨论欲
- `novelty`：20% —— 新鲜、信息差、还没讲烂
- `importance`：15% —— **对用户的实际影响**，不是公司估值或融资规模

最终 `radarScore` 宁可偏低也不要硬抬。当天只有 5 条真正好，就发 5 条。

在其他条件接近时，**GitHub Trending 上有真实免费 / 开源使用路径、能直接安装或复制的项目，优先级高于功能相近的收费网页工具。** 但这不是硬配额，项目如果太生涩、太底层、没有直接帮助，仍然淘汰。

`whyItMatters` 必须写**用户为什么在乎 / 能拿走什么**，禁止写空泛的“这说明行业正在进入新阶段”。

## 5. 典型正例，用来校准“什么叫值得发”

### 正例 1：Anthropic Skills / HTML 动画

Anthropic 社区里有可直接使用的 Skills，可以把复杂内容转成通俗易懂的 HTML 动画。用户看到后能立刻去试，结果可视化，传播门槛低。

- https://github.com/anthropics/claude-plugins-community
- https://github.com/anthropics/claude-plugins-community/tree/main

### 正例 2：两周 AI Crash Course

一个传统软件创业者为了快速补齐这一轮 AI 知识，整理了两周学习路径：Transformer、Scaling Law、RLHF、MoE → CoT、ReAct、DeepSeek R1 → Tool Use、Coding Agent → SWE-Bench / Eval，并给重点论文打 `*`。

价值不在“论文多”，而在于：**别人已经替你筛过、排好顺序，你可以直接照着学。**

### 反例

- “某某高管离职 / 某公司融资数十亿 / 某公司收购某公司”——多数普通人没有获得感。
- “某模型底层架构增加某能力”——如果用户体验没有变化，不推荐。
- “某论文提出一个复杂新理论”——如果没有可用结果、Demo 或现实影响，不推荐。
- “GitHub Trending 上一个很复杂的 Agent 基础设施项目”——如果普通用户看完仍不知道今天怎么用、能省什么，不因 Star 多或开源就推荐。

## 6. 最终输出与发布检查

每条最终候选至少要有：`title / url / publishedAt / category / summary / whyItMatters / angles / source / radarScore`。

发布前最后检查：

- 时间真的在 24h 内，或者 GitHub 项目的**当日 Trending / 涨星爆发**确实发生在本轮窗口？
- GitHub Trending 是否已作为头等来源优先扫描，而不是只拿来做验证？
- GitHub 项目是否有真实免费 / 开源可用路径？如果依赖收费服务，是否写清楚？
- 一手信源核验过？
- 同一件事去重了？
- 普通用户能看懂？
- Agent / Skill / Coding 工具是否足够简单具体，能直接帮到用户，而不是只有理论价值？
- 有“我想试 / 我想收藏 / 我想转给别人”的理由？
- `whyItMatters` 写的是用户价值，而不是行业黑话？
- archive、report、latest 三份都更新？
- GitHub Actions 已 `completed + success`？
- 线上页面亲自检查过？

全部通过，才算本轮 X 情报雷达完成。
