# X产品部

专门研究 X 发帖话术、内容表达、开头钩子、段落节奏、个人判断与可传播性。

核心参考方向：泊舟老师的文风。重点不是机械模仿，而是持续拆解其表达方式，并沉淀成可复用的 X 发帖方法。

## 主要研究内容

- X 发帖话术
- 泊舟风格拆解
- 高赞帖子结构与表达
- 开头钩子与短句设计
- 句子长短与段落节奏
- 个人判断、使用感与“去 AI 味”表达
- 同一选题不同写法的 A/B 测试
- 失败样本与低浏览量帖子复盘

## X 情报雷达执行规则

### 强制前置阅读

以后凡是执行“今天 X 情报”“过去一天 X 情报”“补充 X 情报源”“更新 X 雷达”“扫今天值得发的内容”等任务，**开始检索之前必须完整读取以下两份文档，不得只依赖记忆执行：**

1. `X情报雷达固定情报源扫描手册.md`：逐个规定 X、GitHub、Linux DO、V2EX、Hacker News、Reddit、AI HOT、Product Hunt、Hugging Face、论文源、官方源、媒体和中文 X 对标账号分别应该怎么扫、看什么、如何判定成功或失败。
2. `X情报雷达与选题来源.md`：规定发现信号后的时间过滤、一手核验、交叉验证、去重聚类、传播价值判断和选题优先级。

**未读取这两份文档，不得开始当天雷达扫描；未完成规定的固定信源覆盖，不得宣称“雷达扫描完成”。**

### 其他硬规则

- 用户说到“雷达”时，目标是更新前沿部网页/雷达数据，不是把情报列表直接输出到聊天里。
- X 情报雷达必须由当前 ChatGPT 会话使用自身 Web 搜索与研究能力完成抓取、交叉验证、筛选和判断。
- 彻底弃用 DragonCode；禁止调用 DragonCode 或其他外部 LLM API 生成、总结或筛选雷达内容。
- 优先追踪 AI 公司核心成员、研究者、开发者、创业者、投资人和高信号独立创作者在 X 上的新观点、新产品、新工具、新工作流和商业信号。
- 只保留可核验、近期、信息增量明显的内容；重复旧闻、纯情绪、无事实支撑的热帖不进入主雷达。
- 完成研究后，必须直接更新 `radar-data/latest.json`、对应日期存档和日报，由网页读取这些数据展示。
- GitHub 提交不等于网页发布完成。必须等 GitHub Actions 构建与 Pages deploy 成功，并检查线上页面确实显示当天日期与当天内容后，才允许向用户说“已更新完成”。
- 如果用户明确要“小红书选题”，那是另一条流程：直接输出符合小红书标准的选题，不要触发 X 雷达流程。
- 如果用户表述模糊，无法判断是要选题还是雷达更新，先确认目标再执行。

## 当前核心资产

- `X情报雷达固定情报源扫描手册.md`：X 雷达每日执行前的强制前置阅读文档，详细定义每类固定情报源的扫描方法、关注信号、失败处理和审计清单。
- `X情报雷达与选题来源.md`：X 情报发现、验证、筛选与选题漏斗总规则。
